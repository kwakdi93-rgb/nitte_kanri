# 日々の予定

ライブ、通院、日々の約束を管理する日本語のカレンダーアプリです。画面はReact、予定の取得・登録・編集・削除はFastAPIで実装しています。データはSQLiteに保存され、初回起動時にテスト用アカウントと、日本時間の当月・今日・直近のサンプル予定を作成します。ログインした会員の予定だけを表示します。

## 必要な環境

- Python 3.12以上
- Node.js 22.12以上、または24系
- npm

## 起動

以下のコマンドはすべて保存先のルートディレクトリで実行します。

```bash
cd /workspace/nitte_kanri
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
npm ci
npm run build
.venv/bin/uvicorn backend.main:app --host 0.0.0.0 --port 8000
```

FastAPIが8000番ポートで画面とAPIを配信します。稼働確認は次のコマンドで行えます。

```bash
curl --fail http://127.0.0.1:8000/api/health
```

## 開発時の自動更新

別々のターミナルで次のコマンドを実行します。

```bash
.venv/bin/uvicorn backend.main:app --reload --host 0.0.0.0 --port 8000
```

```bash
npm run dev
```

Viteの開発サーバーは`/api`へのリクエストをFastAPIの8000番ポートへ転送します。画面の変更はViteが、Pythonの変更はUvicornが自動反映します。

## ログイン

初回起動時に次のアカウントを作成します。

| 名前 | ログインID | 初期パスワード | ログイン後の画面 |
| --- | --- | --- | --- |
| 管理者 | `administer` | `12345678` | 会員管理 |
| テストユーザー1 | `test1` | `12345678` | 自分のカレンダー |
| テストユーザー2 | `test2` | `12345678` | 自分のカレンダー |

ログイン画面は`/login`、会員のカレンダーは`/calendar`、管理者の会員管理画面は`/admin`です。ログイン状態と権限に応じて表示を切り替えます。

ログイン画面のデモアカウントを選ぶと、初期情報を入力できます。管理者が情報を変更した後は、変更後のログインID・パスワードを使用してください。

管理者は会員一覧から名前・ログインID・パスワードを編集できます。パスワード欄を空欄にすると現在のパスワードを維持します。既存のパスワードは表示しません。ログインIDまたはパスワードを変更すると、その会員のセッションは失効し、再ログインが必要になります。名前だけの変更ではログインを維持します。

会員ごとの予定は内部の会員番号に紐付くため、ログインIDを変更しても消えません。他の会員の予定や、会員から管理者用の機能にはアクセスできません。会員の新規登録・削除は今回の機能に含みません。

## 使い方

- 月間カレンダーで日付を選ぶと、その日の予定を確認できます。
- 「予定を追加」から予定名・日付・開始時間・終了時間・種類・場所を入力します。
- 種類は「ライブ」「通院」「その他」です。
- 予定を選ぶと詳細を表示し、編集・削除できます。
- 種類ごとの絞り込みと予定一覧の表示に対応しています。

終了時間と場所は省略できます。終了時間を入力する場合は、同日の開始時間より後に設定します。

## データの保存

初回起動時に`data/calendar.sqlite3`を作成します。登録した予定はサーバーを再起動しても残ります。すべての予定を削除した後も、サンプル予定が自動で復活することはありません。

保存先は環境変数`CALENDAR_DB_PATH`で変更できます。サンプルからやり直す場合は、サーバーを停止し、必要な予定を保管したうえでデータベースファイルを削除してから再起動します。

旧バージョンの共通予定は、初回の移行で`test1`の予定として保持します。`test2`には別のサンプル予定を作成します。既存データの削除や、変更済みのログイン情報の初期化は行いません。

パスワードはソルト付きハッシュ、ログイン状態はサーバー側のセッションとHttpOnly Cookieで管理します。セッションの有効期限は12時間で、ログアウト時に失効します。変更系APIには`X-Requested-With: XMLHttpRequest`ヘッダーが必要です。画面からの操作では自動的に付与します。

初期アカウントは動作確認用です。今回の管理画面は一般会員の編集を対象とし、管理者自身のパスワード変更画面は含みません。公開運用には、管理者を含む初期認証情報の変更手順とHTTPSの設定が別途必要です。外部カレンダー連携は含まれていません。

## 検証

```bash
.venv/bin/python -m pytest backend/tests -q
npm test
npm run build
```

APIの検証では、一時データベースでログイン・ログアウト・権限確認、会員間の予定分離、会員情報の変更、既存データの移行、再起動後の保存、入力値の検証を確認します。

## API

| メソッド | パス | 処理 |
| --- | --- | --- |
| GET | `/api/health` | 稼働状態を確認 |
| POST | `/api/auth/login` | ログイン |
| GET | `/api/auth/me` | ログイン中の会員を取得 |
| POST | `/api/auth/logout` | ログアウト |
| GET | `/api/admin/users` | 一般会員の一覧を取得（管理者のみ） |
| PUT | `/api/admin/users/{id}` | 会員情報を更新（管理者のみ） |
| GET | `/api/events` | 自分の予定を日付・時間順に取得 |
| POST | `/api/events` | 予定を登録 |
| PUT | `/api/events/{id}` | 予定を更新 |
| DELETE | `/api/events/{id}` | 予定を削除 |

予定の項目は`id`、`title`、`date`、`start`、`end`、`category`、`location`です。`id`はサーバーが生成します。日付は`YYYY-MM-DD`、時間は`HH:MM`形式です。種類の送信値は`live`（ライブ）、`medical`（通院）、`other`（その他）です。
